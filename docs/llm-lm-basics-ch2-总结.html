问题 ①

思考强度,和温度 / top-k / top-p 是什么关系

核心答案:两族旋钮,各管一段,互不替代。 思考强度管想多久(生成预算:思考链多长);温度 / top-k / top-p 管每一步怎么从分布里挑词(采样规则)。
旋钮管什么作用点白话
思考强度思考链长度 / 推理预算整个生成过程(总共产出多少思考 token)先想再答,想多久
温度 τ分布形状每一步采样前,logits 除以 τ 再过 softmaxτ<1 拉尖(接近贪心),τ>1 拉平(更随机)
top-k候选个数每一步采样时,只留概率前 k 个硬砍长尾,砍多少个
top-p候选累计概率每一步采样时,留到累计概率达 p 的最小集合核大小自适应:模型笃定核就小,犹豫核就大

怎么配合:思考强度不改变分布形状;温度/top-k/top-p 照样作用于思考链与最终回答的每一个采样步。 组合效果:高思考 + 低温度 = 长而稳;低思考 + 高温度 = 短而发散。 钉到 2.7 节:这四个全是方式二(生成)的旋钮;方式一(打分)不采样,温度/top-k/top-p 用不上,也没有"思考"可言。 工程注:解码策略只在推理期起作用,不改模型权重(教材 2.6.6);有的产品里"思考强度"还隐含"是否先思考"的开关,概念上都是推理预算。

问题 ②

为什么评测与 RLHF 大量使用方式一

教材 2.7:同一个语言模型,被当作两台不同的机器用。

方式一:概率估计器(打分)方式二:生成器(采样)
干什么输入完整序列,输出它的对数似然或某位置的条件概率反复"采样 → 拼回输入",自回归地产出新文本
成本一次前向,所有位置概率并行出T 个 token 要 T 次前向(串行,KV Cache 为削减重复计算而生)
用途文本分类(比候选标签概率)、重排序、PPL 流畅度、RLHF 的逐 token 对数概率对话、写作、代码补全

理由一 · 任务性质:评测与 RLHF 的关键计算是给已有文本打分,不是写新文本。 · 评测:比较各候选答案续写的概率(选最大者),或算 PPL——本身就是方式一。 · RLHF(PPO/GRPO):对已经生成好的序列逐 token 算对数概率,用来估计策略梯度。 理由二 · 便宜:方式一一次前向全并行;方式二 T 次串行前向,贵得多。 理由三 · 确定可比:打分是确定数值,不掺采样随机性——只有确定的数才配当"度量"和训练信号。

别误会:RLHF 里"采样回答"(rollout)那一步确实用方式二;但"给回答算概率、算梯度信号"这一步用方式一——"大量"指的是后者。两台机器,底层是同一个条件分布。
问题 ③

交叉熵损失与困惑度:是取代关系吗,训练用谁

核心答案:不是取代,是同一个量的两种刻度。 PPL = e(平均交叉熵)。训练时反向传播用交叉熵,监控与汇报看困惑度——训练日志里那两个数,其实是同一个东西。
每个位置:  CE = −log P(真实下一词)        // 单位 nats
整段文本:  PPL = exp(所有位置的平均 CE)   // 把对数刻度翻译回"候选个数"

白话对照:交叉熵是对数刻度的损失;困惑度把它翻译回人话——"每一步等效在多少个候选里均匀犹豫"。 PPL = 1:每步都完美确定;PPL = k:等效在 k 个词里均匀犹豫;随机模型 PPL ≈ 词表大小 |V|。 数学上:exp 严格递增,所以"降 CE"就是"降 PPL"——选谁当优化目标,结果等价。 工程上:直接用 CE。它是可微的原始损失,梯度形式极简(softmax 概率 − one-hot);没必要再套一层 exp,那只会放大数值、增加溢出风险。

同一组数,两种读法(拖动滑块感受)

平均 CE = 4.0 nats → PPL = 54.6
平均交叉熵(nats)PPL白话
1.02.7不到 3 个候选里犹豫
2.0 ~ 3.07.4 ~ 20好的现代模型在自然文本上的常见区间(个位数到十几)
4.055在约 55 个候选里犹豫
10.82≈ 50,000词表 5 万时的随机模型基线(PPL ≈ |V|)

注意一:PPL 只在同一分词器 + 同一数据集下可比——不同词表的"每 token 熵"不能直接比。 注意二:PPL 低 ≠ 生成质量高——背下训练集的模型 PPL 极低,但毫无用处;最终评测仍需任务级指标。

问题 ④

n-gram 里的 gram 是什么含义

词源:gram 来自希腊语 gramma(文字、书写的东西);后缀 -gram = "写出来的东西 / 一条记录"。 同款词:telegram = tele(远)+ gram(文字)→ 远方来的文字 = 电报;diagram = 图。 在 n-gram 里:gram = 一个书写单元(词或字);n-gram = n 个连续单元组成的片段,n 叫阶数。bigram = 2 个,trigram = 3 个。 不是 grammar(语法),也不是重量单位"克"。

例句「猫 追 了 老鼠」切出的片段
bigram(2 阶)(猫,追) (追,了) (了,老鼠)
trigram(3 阶)(猫,追,了) (追,了,老鼠)

钉回教材 2.3:n-gram 模型只看最近 n−1 个词(马尔可夫假设),用计数估条件概率——绝大多数组合没见过,这就是"稀疏性"。 也正是第 1 章 NNLM 用分布式表示补的那个漏,见 教材第 1 章。

马尔可夫假设 + 最大似然计数:n-gram 的概率表是怎么填出来的

核心答案:马尔可夫假设负责"把看多长的历史砍短",最大似然计数负责"用语料出现次数把概率填出来"。两者合起来就是 n-gram 模型。
完整前文:    P(wₜ | w₁,…,wₜ₋₁)                    // 历史随句子无限变长
马尔可夫截断: P(wₜ | 最近 n−1 个词)                  // 把历史硬砍到固定长度
最大似然计数: P(wₜ | h) = C(h, wₜ) / C(h)           // 出现频率直接当概率

马尔可夫假设:来自马尔可夫性质"未来只取决于当前状态";在 n-gram 里,当前状态 = 最近 n−1 个词,更早的历史全部丢掉。 最大似然估计(MLE):选一组概率参数,使训练语料出现的概率最大;对 n-gram,解就是"接在历史 h 后面的频率"。

n 越大,看得越远

模型n预测时看的历史例子
unigram1不看历史P(苹果)
bigram2最近 1 个词P(苹果 | 吃)
trigram3最近 2 个词P(苹果 | 想 吃)
完整语言模型不截断全部前文P(苹果 | 我 今天 想 吃)

最大似然计数:数数就是求最大似然

语料统计项次数由此估出的条件概率
"我 吃"总共出现50—
"我 吃 苹果"出现10P(苹果|我 吃) = 10/50 = 0.2
"我 吃 面条"出现30P(面条|我 吃) = 30/50 = 0.6
"我 吃"后接其他10P(其他|我 吃) = 10/50 = 0.2

为什么数数 = 最大似然:设 p = P(苹果|我 吃),50 次里 10 次接苹果,似然 L(p) = p¹⁰(1−p)⁴⁰;让它最大的 p 正好是 10/50 = 0.2。

两个部件各干什么 + 代价

部件解决的问题代价
马尔可夫假设前文太长、组合爆炸——词表 5 万、看 5 个词的历史就有 50000⁶ ≈ 1.5×10²⁷ 种组合窗口外的信息看不见:长距离依赖(如句首的"猫")丢失
最大似然计数概率从哪来——直接数频率,快、可解释、数据少也能跑没见过的组合计数为 0,概率为 0,整句概率归零(稀疏性)

使用场景:神经网络之前用于语音识别候选打分、输入法/拼写纠错、早期机器翻译流畅度、文本检索;马尔可夫假设本身还用在 HMM、马尔可夫链、强化学习 MDP。 与 GPT 的分界:GPT 不做硬截断,在上下文窗口内看完整前文,靠 attention 自己学"哪些前文词重要";n-gram 是人工规定"只看最近几个词"。

似然是什么:定义、原则、算法,三层别混

核心答案:似然 = 给每组参数打的"解释数据能力"的分数(定义);最大似然 = 选最高分的规则(原则);交叉熵训练 = 用梯度实现这条规则(算法)。

同一个函数 L(θ) = P(数据 | θ),两种读法:

概率似然
已知参数(如:骰子均匀)数据(如:10 次里 6 出现 4 次)
变量数据参数
回答"会出现什么结果?""哪个参数更像真的?"
白话顺着假设推现象顺着现象反推假设(侦探破案思维)

似然 ≠ 概率分布:所有参数的似然加起来不等于 1,它只在候选参数之间比大小时有用。 骰子例:10 次出 4 个 6——均匀骰子 L≈0.00054,动过手脚(每次 0.4)的骰子 L≈0.00119,后者似然更高,更像真的。

哪些是假设,哪些不是

内容性质
数据样本相互独立假设
模型族是 n-gram 表 / 神经网络假设(规定候选参数长什么样)
只看最近 n−1 个词假设(马尔可夫截断)
整句概率拆成 ∏ₜ P(xₜ | xₜ₋₁…)不是假设:链式法则,恒等式
CE = −(1/N)·log L(θ)不是假设:公式推导

自回归训练就是在最大化似然

log L(θ) = Σₜ log P_θ(xₜ | xₜ₋₁…)
CE      = −(1/N)·log L(θ)          // 最小化 CE = 最大化对数似然

n-gram:   有闭式解 → 直接数数 C(h,w)/C(h)
神经网络:  没有闭式解 → 反向传播 + 梯度下降,一点点爬向似然更高处

不是"训练本身就能做到似然",而是:自回归训练就是在最大化似然,只是解法从"数数"换成了"梯度"。 限制:最大似然只在模型族内挑最好的——bigram 即使最优也看不见句首的"猫";数学上等价于最小化数据分布与模型分布的 KL 散度。

问题 ⑤

同一段文本,生成 / 打分 / 训练到底差在哪

总钥匙:不是有三套模型,而是同一个条件分布的三种用法;因果遮罩始终在场,改变的是"算完概率以后做什么"。

同一段文本:答案写在输入里,也不能偷看未来

核心:因果遮罩遮的是 attention 的信息通道,不是删除文本。每个位置只能读自己和左边,再用这份左侧信息预测右边一个 token。
中国的首都是上海

为把图画清楚,这里假设一个汉字就是一个 token;真实模型由分词器切分。

因果遮罩矩阵:每一行看"当前位置能读谁"

当前位置 ↓中国的首都是上海
中自己×××××××
国✓自己××××××
的✓✓自己×××××
首✓✓✓自己××××
都✓✓✓✓自己×××
是✓✓✓✓✓自己××
上✓✓✓✓✓✓自己×
海✓✓✓✓✓✓✓自己
蓝 = 当前位置自己绿 = 左侧可见灰 × = 未来禁止
scores  = Q·Kᵀ / √d_k       // 先算当前位置对所有位置的相关度
scores[未来位置] = −∞        // softmax 之前下闸
weights = softmax(scores)    // 未来位置权重变 0
output  = weights·V          // 未来信息进不来

看"是"这一行:它能读"中国的首都是",看不到"上海",所以可以给"上"公平打分。 看"上"这一行:它能读"中国的首都是上",看不到"海",所以可以给"海"公平打分。 数学结果:softmax(−∞) = 0;未来 token 仍在输入矩阵里,但 attention 分配给它的权重是 0。

同一概率分布:模型首选"北",标准答案却是"上"

在位置"是"上,模型读完 中国的首都是,输出下一 token 的条件概率分布:

北
70%
上
5%
南
2%
其他
23%

符号钉死:P(上 | 中国的首都是) = 0.05,是"上"的条件概率,不是前面整段 prompt 的概率。 第一名与答案:"北"是模型首选;"上"是已有文本里的真实下一 token。两者不一致时,三种用途走向三条路。

生成:没有标准答案,负责选

输入:中国的首都是 ↓ 贪心:选第一名北 ↓ 下一步可能续出京 不比较"上",不算 CE,不更新

打分:已有标准答案,负责记账

输入:中国的首都是上海 ↓ 不选"北",直接查P(上)=0.05 ↓ CE = −ln(0.05) = 3.00 记下低分,不反向传播,不更新

训练:先记账,再改模型

前向与打分相同,也得到 CE = 3.00 ↓ 反向传播,计算梯度 ↓ 优化器小幅更新权重 类似上下文中提高"上"的分数
正常对话为什么不会自动纠错?生成时手里没有标准答案"上",就没有"不一致"可供比较;只有打分和训练把已有文本当目标。即使训练时第一名猜对,只要概率不是 100%,CE 仍会继续推动模型提高真实答案的概率。

一次前向为什么能算完整段:每个位置都在预测自己的下一词

打分与训练使用 teacher forcing(教师强制):每一步都把真实前缀给模型,不把模型刚才的首选接回去。

要评的真实 token遮罩后可用条件模型给真实 token 的概率此位置 CE
上中国的首都是0.05−ln(0.05) ≈ 3.00
海中国的首都是上0.20−ln(0.20) ≈ 1.61
预测"海"时使用:中国的首都是上→海

即使模型刚才最想要"北",给"海"打分时仍用真实的"上",不是用模型生成的"北"。

候选"上海"的总对数概率 = ln(0.05) + ln(0.20) = ln(0.01) ≈ −4.605
平均 CE = (3.00 + 1.61) / 2 ≈ 2.303
候选 PPL = exp(2.303) = 10.0

总对照:同一段文本,差别全在概率算完以后

生成给已有文本打分训练
目的产新文本评价已有文本让模型拟合已有文本
输入prompt + 已生成前缀prompt + 完整候选答案完整训练文本
因果遮罩有有有
概率算完后选一个 token 接回输入读取真实 token 的概率读取真实 token 的概率
温度 / top-k / top-p采样时参与不参与不参与
交叉熵不算算,作为分数算,作为损失
反向传播 + 更新权重没有没有有
一句话钉死:生成 = 前向 + 选词;打分 = 前向 + 记账;训练 = 前向 + 记账 + 反向传播 + 更新。三者都用因果遮罩,也都使用"前面 n 个 token → 下一个 token 的条件概率分布"。
